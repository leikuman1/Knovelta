# Knovelta

基于 Vercel AI SDK 的本地个人知识维护应用。输入知识后，Agent 搜索和阅读已有笔记，生成新增、补充或冲突提案；用户查看 Diff 并批准后，受控后端才提交 Markdown、版本、来源及检索索引。

当前实现范围为 [Phase 1](docs/phrase-01.md)：单用户、单 Agent、本地运行。包含 Chat、Notes、Change Review、History，以及拒绝、乐观版本锁、历史恢复与失败恢复。向量检索、LangSmith、导入、MCP 和自动回顾留待后续。

## 本机运行

需要 Node.js 24（至少 24.9）及 npm。SQLite 为嵌入式数据库，无须启动单独服务。

1. 在项目目录执行 `npm ci`。
2. 将 `.env.example` 复制为 `.env.local`，填写模型配置：

   ```dotenv
   LLM_BASE_URL=https://你的服务地址/v1
   LLM_API_KEY=你的密钥
   LLM_MODEL=实际模型ID
   MEMOAGENT_DATA_DIR=./data
   ```

   接口必须支持 OpenAI Chat Completions、流式输出及工具调用。`/v1` 是否需要由服务商决定。配置仅在服务端使用，`.env.local` 与数据目录均被 Git 忽略。不要提交密钥。

3. 执行 `npm run dev`，打开 <http://127.0.0.1:3000>。首次读取时自动初始化数据库并检查未完成提交。
4. 生产模式使用 `npm run build` 后执行 `npm start`，同样仅监听本机。

模型配置缺失时仍可浏览已有笔记；新输入先保存原文，再提示模型配置问题。修正环境变量后重启服务，在对话中使用重试可复用原请求 ID。审批验证令牌过期时刷新页面。

## 从空库演示

1. 输入“记一下，Checkpointer 用于持久化图状态”，点击发送。
2. 在右侧打开 CREATE 提案，查看新增 Diff、理由及原文，点击“批准变更”，得到 v1。
3. 输入“补充上次的 Checkpointer 笔记：thread_id 用于标识会话”，核对 UPDATE 指向原笔记，再批准得到 v2。
4. 提问“我记过的 Checkpointer 和 thread_id 有什么作用？”，点击已校验引用查看指定版本和原始来源。
5. 再提出一次补充，拒绝提案，确认正文与版本未变。
6. 打开笔记历史，点击“预览恢复 v1”，核对 Diff 后批准，得到正文和来源集合与 v1 一致的 v3。v2 继续保留。
7. 在审计记录中查看审批、提交、拒绝与恢复记录。

存在两个同基础版本的提案时，批准一个会使另一个提交返回 409。重新读取并生成提案后再审批。

## 数据与恢复

```text
data/
  raw/                原始输入，只追加
  wiki/               最新已提交整理正文
  versions/           各已提交版本的不可变 Markdown 快照
  staging/            提交临时文件
  memoagent.sqlite    元数据、操作状态、版本来源、审计和 FTS5
```

路径由 UUID 映射，不以用户标题或模型路径作为文件名。笔记与检索内容只作为数据；模型工具不包含批准、拒绝、恢复或任意文件执行。Markdown 不执行原始 HTML。

Markdown 与 SQLite 无法共用事务。提交先持久化用户批准和操作记录，生成快照，替换文件，再在数据库事务中更新版本、来源、FTS 和审计。数据库提交前，读取仍使用上一已提交快照。启动时依据状态和哈希继续已有获批操作，未恢复操作会阻止后续正文提交。

如遇“需要恢复”，先停止应用，再运行：

```sh
npm run recover
```

该命令读取 `.env.local` 的数据目录。已提交 wiki 缺失时可从可信快照恢复；未知外部修改或快照损坏会保留现场并停止自动覆盖。检查返回信息，在修复前备份完整数据目录。外部 Markdown 编辑与增量索引不属于 Phase 1，请通过应用提案更新正文。

仅运行一个应用实例。恢复脚本也应在应用停止后执行。代码使用数据库写入约束及恢复锁，但不提供多进程部署或共享网络磁盘支持。文件替换并不保证磁盘损坏或断电后绝对无损。

## 检查与测试

```sh
npm run typecheck
npm run lint
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

服务测试使用临时目录和 SQLite，覆盖审批/拒绝、冲突、幂等、版本恢复、中文 FTS5、来源校验、注入和多个写入故障边界。Agent 与浏览器测试通过本地 OpenAI 兼容测试服务驱动真实 AI SDK 工具调用；不需要密钥，也不会产生模型费用。测试服务不属于生产应用，应用没有自动审批或模拟提案后门。

GitHub Actions 在 Linux 和 Windows 运行类型、Lint、测试和构建；另在 Linux 运行 Chromium 审批与回滚链路。CI 不读取真实模型密钥或个人笔记。

真实模型连接可使用：

```sh
npm run smoke
```

该脚本使用隔离临时数据目录，会调用你配置的模型并产生相应费用，只生成提案和查询，不自动批准正文。真实模型的完整新增、补充、冲突和问答需按上方 UI 演示验收。自动化使用确定性测试接口通过，不能据此声称真实模型准确率。

## 当前边界

- 不自动删除数据或重写多个笔记。每次只审批一篇笔记。
- FTS5 使用中文分词、汉字词项和英文/API 词项，仅检索最新获批正文；语义改写与同义词仍可能漏召回。
- 引用校验保证 ID、版本和摘录存在；结论是否由材料充分支持仍需内容审阅。
- 对话请求内完成 AI 处理，最多 8 个模型步骤、12 次工具调用、60 秒；重启不自动续跑模型。
- 尚未建立 50 条人工审核留出评测集；不提供准确率、Recall 或性能提升承诺。
- 本地审批接口使用同源校验和签名防伪令牌，不提供多人身份认证。不要将服务公开到公网。
