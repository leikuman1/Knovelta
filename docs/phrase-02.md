# Knovelta Phase 2：前端设计统一与桌面主页面重构

> 记录日期：2026-10-29。  
> 状态：桌面主页面试改已完成，全项目配色进一步统一为雾蓝主题；布局与组件结构尚未全面改造。  
> 设计依据：[DESIGN.MD](../DESIGN.MD) 与用户提供的「雾蓝水彩 · 私人知识图鉴 Design System v2.1」。  
> 本文记录此次前端工作，不表示原始规格中的 Phase 2 检索增强、可观测性或其他产品功能已获实施授权。

## 1. 目标与范围

在已有 Phase 1 可靠知识写入与问答闭环上，建立可复用的前端视觉基线，先把桌面主页面做好。用户确认桌面布局、视觉与交互后，再逐步推广到其他视图，最后推进平板与手机的专项适配。

累计改造包括知识库导航、对话首页、输入区、有内容的对话，以及主页面使用的字体、间距、圆角和焦点规则。随后按用户明确要求，将颜色统一扩展到全项目现有视图：笔记正文、变更审阅、引用卡片、来源详情、版本历史、操作历史及其状态。此次扩展仅调整配色，现有布局和交互结构保留，审批、原文留存、真实引用、版本校验、冲突处理与恢复机制继续保留。

本轮未实施新的业务能力、存储格式迁移、三栏任务重排、角色插画、字体下载、组件库迁移或 npm / Windows 安装包。

## 2. 设计方向

视觉从冷灰与深绿调整为雾蓝、灰白和墨蓝。侧栏形成轻薄的索引区域，正文使用纸白阅读画布，墨蓝承担主动作、链接与选中标记。通过留白、细分隔线和清晰层级组织内容，避免大渐变、发光卡片、厚重投影和过度嵌套卡片。

用户提供的完整参考还包含书册章节、书签、旁注、水彩笔触与原创角色。这些属于后续设计候选；此次只落实色调，不把换色视为完整水彩或日系手账风格已经完成。

### 2.1 当前颜色基线

| 用途 | Token | 值 |
| --- | --- | --- |
| 全局背景 | `--color-canvas` | `#F2F6FA` |
| 纸白画布 | `--color-surface` | `#FEFEFF` |
| 雾蓝侧栏与次级区域 | `--color-surface-subtle` | `#EAF1F7` |
| 结构边界 | `--color-border` | `#C5D3E0` |
| 辅助分隔线 | `--color-divider` | `#D3DEE9` |
| 正文与标题 | `--color-text` | `#4F6174` |
| 白底辅助文字 | `--color-text-secondary` | `#5F7186` |
| 浅蓝底辅助文字 | `--color-text-muted` | `#56697D` |
| 控件边界 | `--color-border-control` | `#8294A6` |
| 浅蓝底控件边界 | `--color-border-control-on-mist` | `#788B9E` |
| 主动作与焦点 | `--color-accent` / `--color-focus` | `#536C87` |
| 主动作悬停 | `--color-accent-hover` | `#455C76` |
| 浅蓝选中填充 | `--color-accent-subtle` | `#DDEAF4` |
| 水彩辅助线 | `--color-watercolor` | `#9EB9D2` |

`--color-paper` 引用纸白画布，悬停填充与选中填充共用同一浅蓝色值。成功、警告、错误与 Diff 保持独立语义色，不作为 UI 装饰品牌色，状态仍由文字、图标或加减号表达。

参考色表做了两处可读性修正：`#5F7186` 在雾蓝和选中浅蓝上分别约 4.39:1、4.09:1，浅蓝底辅助文字因此使用 `#56697D`，分别约 4.96:1、4.62:1；必要控件边界在浅蓝状态使用 `#788B9E`，在雾蓝上约 3.08:1。正文在纸白上约 6.32:1，主按钮白字在墨蓝上约 5.44:1。

### 2.2 排版与结构

- 使用系统字体，无远程字体请求；正文 16px / 28px，常规 UI 14px / 20px，辅助信息 12px / 18px。
- 通过统一的 4、8、12、16、24、32、40、48px 间距尺度组织内容。
- 桌面侧栏起始宽度 240px，主内容容器上限 760px，输入区与内容对齐。
- 首页使用「记录与提问」及直接的任务说明，输入示例采用列表与细分隔线。
- 现有主页面圆角与布局本轮保留；参考中 8–10px 按钮、书册装饰与新面板分工尚未推广实施。

## 3. 已实现的前端重构

| 范围 | 实际变化 |
| --- | --- |
| 主题基础 | 在 `globals.css` 集中定义语义颜色与排版、间距、控件尺度；旧视图通过兼容变量读取主题 |
| 主页面样式 | `workspace.css` 集中承载试点规则，减少主页面各区域的临时数值 |
| 首页 | 抽取 `ChatWelcome`，提供记录、查询与补充三类草稿入口；减少口号、装饰底框与重复说明 |
| 导航 | 收紧品牌、知识库与工具栏层级；审阅区域按需展开 |
| 输入 | 统一文字与焦点样式；示例只填草稿，不发送，也不覆盖非空草稿 |
| 对话 | 正文使用舒展排版，保留原文入口、提案入口、错误说明和重试操作 |
| 计数 | 待处理数量与待处理筛选统一包含 pending、applying、needs_recovery |
| 弹层 | 关闭后将焦点返回仍存在的触发控件 |
| 配色 | 全项目清理旧灰绿底色、图标、选中标记、阴影与边框；所有组件配色改用统一语义 Token |
| 状态 | 已提交使用 Success，待审阅/过期/需恢复使用 Warning，提交中使用 Info，拒绝使用 Neutral；Diff 图例与内容共用语义色 |
| 弹层颜色 | 来源、引用、版本历史与操作历史共用纸白面板、蓝灰遮罩及统一浮层阴影 |

此前试改已经包含平板审阅切换、手机面板与草稿保留；这些改动按用户要求保留。用户随后明确桌面优先，本轮没有继续展开平板或手机设计，也没有把旧的多端验证算作此次配色的专项验收。

## 5. 技术取舍

继续使用 Next.js App Router、React、TypeScript、自定义组件、现有 SVG 图标与 CSS。此次没有安装 Tailwind CSS、shadcn/ui、Radix 或 Lucide；它们仍是后续按需评估的方向，不能写成已落地事实。

主题使用语义 Token，避免为了换色重写基础交互。本轮清理了组件规则内的硬编码颜色，颜色数值集中在 `globals.css` 的 `:root`；`layout.tsx` 的浏览器主题元数据同步全局背景色。旧变量名继续引用同一主题，不维护第二套配色。历史字号、间距与覆盖规则仍存在，按后续视图任务逐步整理。

应用未来通过 npm 或 Windows exe 交付仍是讨论方向，本轮没有实现启动器、桌面容器、安装、升级或配置迁移。

## 7. 后续推进与验收边界

1. 用户先评审桌面主页面的色调、信息密度与输入体验。
2. 确认后选择下一个视图，优先解决变更审阅的阅读空间、版本、来源与 Diff 层级。
3. 保持全项目雾蓝语义 Token 单一来源；后续新增视图和交互状态遵循 `DESIGN.MD` 的全局颜色职责，继续按需整理历史样式覆盖。
4. 书册编号、旁注、可复用水彩素材与原创角色另行确认；不为装饰牺牲正文可读性。
5. 桌面体验稳定后，再推进平板与手机专项适配。未经验证不大规模推广。

本次前端改动、设计文档和已有经验记录按用户明确要求纳入此次 PR。后续产品特色、检索增强与分发打包各自单独确认范围。
